# BakiBuddy mobile foundation

Mode: Operate. Scope: Phase 1 only, five phone screens.

The supplied brief pins the identity and authorizes sensible defaults without another design approval. Build directly in React Native rather than introducing a raster mockup approval step. This is a session implementation choice, not a stored workflow preference.

## Direction contract

Unique mechanism: a future income-cycle allowance makes a balance meaningful for everyday Malaysian spending. The first viewport illustrates that mechanism with explicitly fictional values.

Grounded directions considered: a bank passbook, an allowance envelope, a campus timetable, an eWallet receipt, a household ledger, a daily planner, and a savings stamp card. Assigned candidate 6 is the daily planner: a calm chronological reading order, date-aware upcoming bills, and useful amounts immediately visible.

First viewport: compact BakiBuddy wordmark and demo badge; personal greeting; one emerald balance surface; a quiet daily allowance preview; clear future-action labels. Follow with chronological bills and transaction rows. Keep density practical and typography tabular for money. Brand expression lives in the wallet mark, emerald field, and careful type, not decorative charts.

Signature interaction: balance visibility toggle with an explicit accessible state; tab navigation uses native tabs on phones. No animated numeric values or unnecessary motion.

Cross-surface reach: the same headings, chronological rows, consistent category symbols, and calm surfaces support future transaction editing, budget details, and consent settings.

The abstract catalog, streaming wall, high-density mosaic, letter grid, center-rail edition, and departure board challengers were declined: coded labels, poster navigation, tiny text, and fixed character grids impede the user's explicit simple-finance/accessibility brief. Their disciplines retained are consistent ordering, clear selected state, efficient rows, alignment, readable references, and visible timing. No borrowed visual costumes.

Risk: static examples can resemble working forecasts. Every screen labels demo data, the preview explains its fixed assumptions, and future actions are disabled with phase labels.

Native evidence constraint: no connected phone or native simulator is available in this Windows workspace. Browser captures are supplemental RN web layout evidence, never native-device verification.
